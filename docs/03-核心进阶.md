> 对应 demo05–demo08。从"只能聊天"进化到"能查数据、能记上下文、能搜网络、能读私有知识"。

## demo05 · 函数调用（Function Calling / Tool Use）

**接口**：`GET /api/demo05/weather?city=杭州`

### 什么是函数调用

LLM 本身不能查天气、查数据库。函数调用让模型在对话中**自主决定**调用你提供的 Java 方法，拿到结果后组织成自然语言回答。

完整循环：

```
用户："杭州今天天气怎么样？"
  → 模型判断需要调用工具
  → Spring AI 调用 WeatherTools.getWeather("杭州", "今天")
  → 返回 "晴，28°C"
  → 模型组织回答："杭州今天天气晴朗，气温 28°C..."
```

### 核心代码

```java
// 工具类：用 @Tool 注解标记方法
public class WeatherTools {
    @Tool(name = "get_weather", description = "查询指定城市的天气")
    public String getWeather(
            @ToolParam(description = "城市名") String city,
            @ToolParam(description = "日期") String date) {
        // 模拟数据（生产环境调真实 API）
        Map<String, String> data = Map.of(
            "北京", "晴，25°C", "上海", "多云，27°C",
            "杭州", "晴，28°C", "广州", "雷阵雨，30°C");
        return data.getOrDefault(city, city + "：暂无天气数据");
    }
}

// Controller：注册工具
ChatClient chatClient = builder.defaultTools(new WeatherTools()).build();

// 调用时不需要改任何代码——模型自动决定是否使用工具
String answer = chatClient.prompt("杭州今天天气怎么样？").call().content();
```

### 教学要点

| 概念 | 说明 |
|------|------|
| `@Tool` | 标记方法为可调用工具，`name` 是模型看到的函数名 |
| `@ToolParam` | 参数描述，模型据此判断该传什么值 |
| `defaultTools()` | 注册到 ChatClient，每次请求模型都可调用 |
| 模拟数据 | 教学用 `Map.of()` 硬编码；生产环境替换为真实 API 调用 |

> **关键理解**：模型不是"被编程"去调用工具，而是根据用户问题和工具描述**自主判断**是否需要调用。这是 Agent 的基础能力。

## demo06 · 会话记忆（Chat Memory）

**接口**：`GET /api/demo06/chat?conversationId=xb&message=我叫小明`

### 问题

LLM 本身无状态——每次请求都是独立的。要让模型"记住"之前的对话，需要外部记忆机制。

### Spring AI 的解法：Advisor 模式

```java
// 全局配置：创建 ChatMemory Bean
@Bean
public ChatMemory chatMemory(ChatModel chatModel) {
    return MessageWindowChatMemory.builder()
        .chatMemoryRepository(new InMemoryChatMemoryRepository())
        .maxMessages(20)    // 滑动窗口：保留最近 20 条消息
        .build();
}

// ChatClient 挂载 Memory Advisor
ChatClient chatClient = builder
    .defaultAdvisors(new MessageChatMemoryAdvisor(chatMemory))
    .build();

// 每次请求传入 conversationId
String answer = chatClient.prompt(message)
    .advisors(a -> a.param("chat_memory_conversation_id", conversationId))
    .call().content();
```

### 记忆隔离

| conversationId | 效果 |
|---------------|------|
| 相同 ID | 共享同一段对话历史（多轮对话） |
| 不同 ID | 完全隔离（多用户/多会话） |

```
用户A (id=xb)：我叫小明 → 模型记住
用户B (id=zs)：你好      → 模型不知道"小明"是谁
用户A (id=xb)：我叫什么？ → 模型回答"小明"
```

### 教学要点

| 组件 | 职责 |
|------|------|
| `ChatMemory` | 记忆存储接口 |
| `MessageWindowChatMemory` | 滑动窗口实现，超过 maxMessages 自动丢弃旧消息 |
| `InMemoryChatMemoryRepository` | 内存存储（教学用）；生产换 Redis |
| `MessageChatMemoryAdvisor` | 在请求前自动注入历史消息到 prompt |

> **生产注意**：内存存储在重启后丢失、不支持多实例。生产用 Redis 或数据库实现 `ChatMemoryRepository`。

## demo07 · 系统角色 + DashScope 联网搜索

**接口**：
- `GET /api/demo07/search?q=今天的新闻`（联网搜索）
- `GET /api/demo07/advice?topic=量子计算&audience=小学生`（动态角色）

### 动态系统角色

```java
// 默认角色
ChatClient chatClient = builder
    .defaultSystem("你是一位博学、幽默的中文科普作者。")
    .build();

// 按请求覆盖角色
String answer = chatClient.prompt(topic)
    .system("你现在是一个给「" + audience + "」讲课的老师，用他们能懂的语言解释。")
    .call().content();
```

### DashScope 联网搜索（阿里独有能力）

```java
String answer = chatClient.prompt(question)
    .options(DashScopeChatOptions.builder()
        .withModel("qwen-plus")
        .withEnableSearch(true)    // 开启联网搜索
        .build())
    .call().content();
```

`withEnableSearch(true)` 是 **DashScope 独有能力**——模型在回答前自动搜索互联网，获取最新信息。这是 Spring AI 官方不提供的，只有通过 `spring-ai-alibaba` 适配层才能使用。

| 场景 | 是否需要联网 |
|------|------------|
| "Java 的 final 关键字" | 不需要（模型训练数据已覆盖） |
| "今天的新闻" | 需要（实时信息） |
| "我们公司的退货政策" | 不需要（应该走 RAG 查私有知识） |

> **教学要点**：联网搜索解决"时效性"问题，但不能替代 RAG——模型搜索到的不是你的私有数据。

## demo08 · RAG 检索增强生成

**接口**：`GET /api/demo08/ask?question=你们几点营业？`

### 为什么需要 RAG

| 方式 | 适用场景 | 局限 |
|------|---------|------|
| 模型自身知识 | 通用常识 | 训练数据有截止日期，不含私有信息 |
| 联网搜索 | 实时公开信息 | 搜不到企业内部文档 |
| **RAG** | **私有知识** | 需要提前将文档向量化入库 |

### 三步 RAG 管线

```
1. 检索（Retrieve）
   用户问题 → 向量化 → 在 VectorStore 中相似度搜索 → 取 top-K 文档片段

2. 组装（Assemble）
   将检索到的文档片段拼接到提示词中作为"参考资料"

3. 生成（Generate）
   模型基于参考资料回答用户问题（而非凭自身知识编造）
```

### 核心代码

```java
// 配置：内存向量库，启动时加载知识库文档
@Bean
public VectorStore vectorStore(EmbeddingModel embeddingModel) {
    SimpleVectorStore store = SimpleVectorStore.builder(embeddingModel).build();
    TextReader reader = new TextReader(new ClassPathResource("kb/shop-intro.txt"));
    store.add(reader.get());     // 文档 → 分块 → 向量化 → 存入
    return store;
}

// 检索
List<Document> docs = vectorStore.similaritySearch(
    SearchRequest.builder().query(question).topK(3).build());

// 组装上下文
String context = docs.stream().map(Document::getText).collect(Collectors.joining("\n---\n"));

// 生成（指示模型只依据资料回答）
String answer = chatClient.prompt()
    .user("请只依据下面的店铺资料回答用户的问题，资料里没有的不要编造。\n\n"
        + "【店铺资料】\n" + context + "\n\n用户问题：" + question)
    .call().content();
```

### 知识库内容（shop-intro.txt）

```
小北咖啡店介绍：
- 营业时间：每天 9:00-22:00
- 招牌饮品：手冲耶加雪菲，38 元
- WiFi 密码：coffee2024
- 地址：杭州市西湖区文三路 188 号
- 会员积分：消费 1 元积 1 分，100 分兑一杯美式
```

### 教学要点

| 组件 | 职责 |
|------|------|
| `SimpleVectorStore` | 内存向量库（教学用）；生产换 Milvus / Elasticsearch |
| `TextReader` | 读取纯文本文档 |
| `EmbeddingModel` | 将文本转为向量（`text-embedding-v3`） |
| `similaritySearch()` | 余弦相似度搜索，返回最相关的文档片段 |

> **关键理解**：这是"手动 RAG"——检索和组装都在代码中显式完成。Spring AI 还提供了 `QuestionAnswerAdvisor` 自动完成这些步骤，但理解底层管线对调试和优化至关重要。

## 小结

| Demo | 解决的问题 | 核心机制 |
|------|-----------|---------|
| 05 | LLM 不能查数据 | `@Tool` 函数调用，模型自主决定何时调用 |
| 06 | LLM 无状态 | `ChatMemory` + Advisor，按 conversationId 隔离 |
| 07 | LLM 不知道最新信息 | DashScope `withEnableSearch(true)` 联网搜索 |
| 08 | LLM 不知道私有知识 | RAG 管线：检索 → 组装 → 生成 |

这四个能力是构建实际 AI 应用的基石。demo10 和 demo11 将它们组合成完整的客服应用。
