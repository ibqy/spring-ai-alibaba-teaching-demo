## demo09 · 列表结构化输出（批量提取）

**接口**：`GET /api/demo09/orders?text=订单A1001买了咖啡30元已支付，订单A1002买了蛋糕25元待支付`

### 从 demo03 到 demo09

| demo03（单对象） | demo09（列表） |
|-----------------|---------------|
| 提取一个演员的信息 | 从自由文本中提取**多条**订单 |
| `.entity(ActorFilm.class)` | `.entity(new ParameterizedTypeReference<List<Demo09Order>>() {})` |

### 核心代码

```java
// 目标类型
public record Demo09Order(String orderId, String item, String price, String status) {}

// 调用：用 ParameterizedTypeReference 表达泛型类型
List<Demo09Order> orders = chatClient.prompt()
    .user("从以下文本中提取所有订单，输出 JSON 数组：" + text)
    .call()
    .entity(new ParameterizedTypeReference<List<Demo09Order>>() {});
```

### 为什么需要 ParameterizedTypeReference

Java 泛型在运行时被擦除——`List<Demo09Order>.class` 不存在。Spring AI 用 `ParameterizedTypeReference` 保留泛型信息：

```java
// 编译错误：Java 不允许
.entity(List<Demo09Order>.class)

// 正确做法：匿名子类保留泛型
.entity(new ParameterizedTypeReference<List<Demo09Order>>() {})
```

### 实际应用场景

| 场景 | 输入 | 输出 |
|------|------|------|
| 聊天记录解析 | "张三说要咖啡，李四要蛋糕" | `[{name:"张三",item:"咖啡"}, ...]` |
| 邮件订单提取 | 自由文本邮件 | 结构化订单列表 |
| 会议纪要 | 会议录音文本 | 待办事项列表 |

> **教学要点**：结构化输出 + 列表是 LLM 作为"数据提取引擎"最实用的场景之一。

## demo10 · 多轮客服机器人（记忆 + 工具 + 角色）

**接口**：`POST /api/demo10/ask`（JSON Body）

### 组合了哪些能力

| 能力 | 来源 | 作用 |
|------|------|------|
| 系统角色 | demo07 | "你是小北咖啡店的智能客服小北" |
| 会话记忆 | demo06 | 多轮对话，记住上下文 |
| 工具调用 | demo05 | 查询售后政策 |
| 联网搜索 | demo07 | 可选，处理实时问题 |

### 请求格式

```json
{
  "conversationId": "user-001",
  "message": "我买的咖啡豆想退货，有什么规定？"
}
```

### 售后工具

```java
public class AfterSalesTool {
    @Tool(name = "query_after_sales", description = "查询商品的售后政策")
    public String queryAfterSales(
            @ToolParam(description = "商品名称") String item) {
        Map<String, String> policies = Map.of(
            "咖啡豆", "7 天无理由退货（未拆封）",
            "咖啡杯", "30 天无理由退货",
            "手冲壶", "15 天内质量问题可换货",
            "挂耳咖啡", "食品类，非质量问题不退货");
        return policies.getOrDefault(item, item + "：暂无售后政策，建议联系客服");
    }
}
```

### 调用流程

```
用户："我买的咖啡豆想退货"
  → 模型识别需要查售后政策
  → 调用 query_after_sales("咖啡豆")
  → 返回 "7 天无理由退货（未拆封）"
  → 模型回答："您好，咖啡豆支持 7 天无理由退货，需要保持未拆封状态哦～"

用户（追问）："那运费谁出？"
  → 模型根据对话历史知道"咖啡豆退货"的上下文
  → 但售后工具没有运费信息
  → 模型诚实回答："运费方面我这边不太确定，帮您转人工客服好吗？"
```

### `/ask-with-search` 端点

与普通 `/ask` 的区别：开启 DashScope 联网搜索。

```java
// 额外开启联网搜索
.options(DashScopeChatOptions.builder()
    .withEnableSearch(true).build())
```

适用场景：用户问"最近有什么新品"——售后工具查不到，但联网搜索可以补充。

> **教学要点**：demo10 是第一个"像样"的 AI 应用——角色 + 记忆 + 工具的组合，已经可以处理真实客服场景。

## demo11 · 高级 Agent（全能力组合）

**接口**：
- `POST /api/demo11/ask`（同步）
- `GET /api/demo11/stream?conversationId=&message=`（SSE 流式）

### 全能力组合

| 能力 | 用途 | 数据源 |
|------|------|--------|
| RAG | 回答店铺基础信息（营业时间、地址等） | `shop-intro.txt` 向量库 |
| 工具调用 | 查询实时业务数据（套餐价格、库存、活动） | `ShopServiceTool`（模拟数据） |
| 会话记忆 | 多轮对话上下文 | `ChatMemory`（按 conversationId 隔离） |
| 联网搜索 | 可选，处理店铺知识之外的问题 | DashScope 联网 |
| 流式输出 | SSE 打字机效果 | `Flux<String>` |

### 三个业务工具

```java
public class ShopServiceTool {

    @Tool(name = "query_menu", description = "查询套餐价格和库存")
    public String queryMenu(@ToolParam String setName) { ... }

    @Tool(name = "query_activity", description = "查询今日/明日优惠活动")
    public String queryActivity(@ToolParam String when) { ... }

    @Tool(name = "list_menu", description = "列出全部套餐")
    public String listMenu() { ... }
}
```

模拟数据包含 5 个套餐（午市单人餐 39 元、双人下午茶 88 元...）和 3 个按星期的促销活动。

### 请求处理管线

```java
@PostMapping("/ask")
public String ask(@Valid @RequestBody Demo11AskRequest request) {
    // 1. RAG 检索
    List<Document> docs = vectorStore.similaritySearch(
        SearchRequest.builder().query(request.message()).topK(3).build());
    String context = docs.stream().map(Document::getText)
        .collect(Collectors.joining("\n---\n"));

    // 2. 组装提示词（RAG 上下文 + 用户问题）
    String userPrompt = "请只依据以下店铺资料回答...\n" + context
        + "\n用户问题：" + request.message();

    // 3. 构建请求（记忆 + 工具 + 可选联网）
    var promptSpec = chatClient.prompt()
        .user(userPrompt)
        .advisors(a -> a.param("chat_memory_conversation_id",
                               request.conversationId()));

    if (Boolean.TRUE.equals(request.enableSearch())) {
        promptSpec = promptSpec.options(DashScopeChatOptions.builder()
            .withEnableSearch(true).build());
    }

    return promptSpec.call().content();
}
```

### 智能路由：模型如何选择数据源

系统提示词明确告诉模型每种信息该从哪里获取：

```
你是"小北咖啡店"的智能客服"小北"。
- 营业时间、地址等店铺介绍 → 只依据【店铺资料】（RAG）
- 套餐价格、库存、优惠 → 调用业务工具查询（Tool）
- 不要编造数字
```

| 用户问题 | 模型选择 | 原因 |
|---------|---------|------|
| "你们几点关门？" | RAG | 店铺资料里有 |
| "午市单人餐多少钱？" | Tool: query_menu | 实时价格数据 |
| "今天有什么活动？" | Tool: query_activity | 按星期变化的促销 |
| "附近有什么景点？" | 联网搜索（如开启）| 非店铺知识 |
| "帮我推荐一个套餐" | RAG + Tool | 先查资料了解菜单，再查库存确认 |

### 流式版本

```java
@GetMapping(value = "/stream", produces = "text/event-stream;charset=UTF-8")
public Flux<String> stream(@RequestParam String conversationId,
                           @RequestParam String message) {
    // 与 /ask 相同的逻辑，但用 .stream() 替代 .call()
    return chatClient.prompt(userPrompt)
        .advisors(a -> a.param("chat_memory_conversation_id", conversationId))
        .stream().content();
}
```

> **教学要点**：demo11 是全课程的收官之作。它展示了 Agent 的核心模式——**基于能力路由**：静态知识走 RAG，动态数据走工具，实时信息走联网，多轮交互走记忆。生产中的 AI 客服、AI 助手都是这个架构的扩展。
