# 基础能力：对话、流式、结构化输出与模板

> 对应 demo01–demo04，Spring AI 的四个最基本操作。每个 Demo 只引入**一个**核心概念。

## 技术前提

- Java 21 + Spring Boot 3.x
- Spring AI Alibaba 1.0.0.2（阿里对 Spring AI 的通义生态适配层）
- DashScope API（通义千问系列模型，默认 `qwen-plus`）

所有 Demo 共享同一个 `ChatClient.Builder`（Spring Boot 自动注入），区别只在于调用方式。

## demo01 · 基础对话

**接口**：`GET /api/demo01/chat?message=你好`
**代码**：[Demo01BasicChatController](../src/main/java/com/xb/springai/controller/demo01/Demo01BasicChatController.java)、[ChatConfig](../src/main/java/com/xb/springai/config/ChatConfig.java)

### 核心代码

```java
// 构造时设置系统角色
ChatClient chatClient = builder.defaultSystem("你是一个博学、友好的中文智能助手。").build();

// 最简调用：直接拿文本
String answer = chatClient.prompt(message).call().content();
```

### 知识点

| API | 作用 |
|-----|------|
| `defaultSystem(...)` | 设置系统角色提示词，所有请求自动携带 |
| `.prompt(msg).call()` | 同步调用，返回 `ChatResponse` |
| `.content()` | 快捷方法，直接取响应文本 |
| `.chatResponse()` | 完整响应，可获取 `finishReason`、`usage` 等元数据 |

`/api/demo01/chat-full` 演示了如何获取完整响应元数据：

```java
ChatResponse resp = chatClient.prompt(message).call().chatResponse();
String text = resp.getResult().getOutput().getText();
FinishReason reason = resp.getResult().getOutput().getMetadata().getFinishReason();
```

> **教学要点**：`content()` 是语法糖，生产代码中通常需要 `chatResponse()` 来获取 token 用量、结束原因等。

## demo02 · 流式对话（SSE）

**接口**：`GET /api/demo02/chat-stream?message=写一首春天的诗`
**代码**：[Demo02StreamingChatController](../src/main/java/com/xb/springai/controller/demo02/Demo02StreamingChatController.java)

### 核心代码

```java
@GetMapping(value = "/chat-stream", produces = "text/event-stream;charset=UTF-8")
public Flux<String> stream(@RequestParam String message) {
    return chatClient.prompt(message).stream().content();
}
```

### 与 demo01 的唯一区别

| 同步（demo01） | 流式（demo02） |
|---------------|---------------|
| `.call().content()` | `.stream().content()` |
| 返回 `String` | 返回 `Flux<String>` |
| 等全部生成完再返回 | 逐 token 推送到客户端 |

`text/event-stream` 是 SSE（Server-Sent Events）的 MIME 类型，浏览器 `EventSource` 或 `fetch` 的 `ReadableStream` 可直接消费。

> **教学要点**：LLM 生成速度慢（秒级），流式输出让用户在第一个 token 到达时就能看到响应，体验提升显著。几乎所有 LLM 产品的"打字机效果"都是这个原理。

## demo03 · 结构化输出（单对象）

**接口**：`GET /api/demo03/actor?actor=周星驰`
**代码**：[Demo03StructuredOutputController](../src/main/java/com/xb/springai/controller/demo03/Demo03StructuredOutputController.java) · [ActorFilm](../src/main/java/com/xb/springai/controller/demo03/ActorFilm.java)

### 核心代码

```java
// 目标类型：Java 21 record
public record ActorFilm(String name, String genre, String famousWork, String reason) {}

// 构建 ReactAgent，指定 outputType
ReactAgent agent = ReactAgent.builder()
    .name("actor_extractor")
    .model(chatModel)
    .outputType(ActorFilm.class)   // 框架自动生成 JSON Schema
    .saver(new MemorySaver())
    .build();

// 调用 Agent，返回 JSON 字符串，手动反序列化
AssistantMessage message = agent.call("请介绍演员" + actor);
ActorFilm result = objectMapper.readValue(message.getText(), ActorFilm.class);
```

### 原理

ReactAgent 通过 `BeanOutputConverter` 根据 POJO 自动生成 JSON Schema，将格式约束注入提示词，引导模型输出符合目标类型结构的 JSON。**开发者只需关注业务逻辑，框架自动处理 Schema 生成**。

| ChatClient 方式 | ReactAgent 方式 |
|----------------|----------------|
| `.entity(Class)` 一步到位 | `.outputType(Class)` + Jackson 反序列化 |
| 适合简单场景 | 适合 Agent 编排、需要记忆/工具的场景 |

> **教学要点**：Agent 级别的结构化输出是构建复杂 Agent 流水线的基础——当 Agent 需要调用工具、保持记忆、同时输出结构化数据时，`ReactAgent.outputType()` 是正确选择。

## demo04 · 提示词模板

**接口**：`GET /api/demo04/poem?topic=春天&style=浪漫`
**代码**：[Demo04PromptTemplateController](../src/main/java/com/xb/springai/controller/demo04/Demo04PromptTemplateController.java)

### 核心代码

```java
String answer = chatClient.prompt()
    .user(u -> u
        .text("请以{style}风格，写一段关于{topic}的短文。")
        .param("topic", topic)
        .param("style", style))
    .call()
    .content();
```

### 类比

类似 JDBC 的 `PreparedStatement`：

```java
// JDBC：模板与参数分离，防 SQL 注入
PreparedStatement ps = conn.prepareStatement("SELECT * FROM user WHERE name = ?");
ps.setString(1, name);

// Spring AI：模板与参数分离，提示词可复用
chatClient.prompt().user(u -> u.text("...{topic}...").param("topic", topic));
```

| 好处 | 说明 |
|------|------|
| 模板可复用 | 同一模板不同参数，不用拼接字符串 |
| 类型安全 | `.param()` 编译期检查 key 名称 |
| 易于管理 | 模板可外置到文件/数据库 |

> **教学要点**：实际项目中提示词往往需要 A/B 测试、版本管理，模板化是基础。

## 小结

| Demo | 核心 API | 一句话 |
|------|---------|--------|
| 01 | `.call().content()` | 最简同步调用 |
| 02 | `.stream().content()` | SSE 流式输出 |
| 03 | `.outputType(Class)` | Agent 结构化输出 → Java 对象 |
| 04 | `.text(tpl).param(k,v)` | 提示词模板变量绑定 |

这四个是 Spring AI 的"Hello World"级能力，后面的所有进阶功能都建立在这四个操作之上。
